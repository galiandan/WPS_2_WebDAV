# 前端拆分与等价迁移计划

> 本文只提供可执行的中文步骤和验收标准，不提供实现代码。
> 执行模型开始工作前，必须先读本目录的总说明、当前系统说明、兼容性契约和目标架构。
> 本文中的“等价”是指用户可见行为、HTTP 请求形状、安全边界和错误状态等价，不要求继续保留 Python 字符串模板这种实现方式。

## 1. 本文目标

1. 把当前嵌在 Python 源文件中的单页文件管理器拆成独立的原生 HTML、CSS 和 JavaScript。
2. 不引入 React、Vue、Svelte、Node.js 构建链、前端路由器、包管理器或运行时 CDN。
3. 第一轮保持现有页面布局、中文文案、交互顺序、REST 请求和连接状态语义。
4. 让 Python 参照服务先能提供拆分后的资源，再让 Go 服务提供同一组资源。
5. 最终使用 Go 的只读资源嵌入能力把网页编入单个服务二进制。
6. 拆分后去掉内联脚本和内联样式，收紧内容安全策略。
7. 用真实浏览器自动化覆盖桌面和移动视口，而不是只检查 HTML 中是否包含某个字符串。

## 2. 必须先接受的事实

1. HTML 和 CSS 只能承担结构与样式，不能完成目录读取、上传、进度监听、重命名、移动、删除和状态轮询。
2. 因此目标技术栈必须写成“Go + HTML + CSS + 原生 JavaScript”，不能删除 JavaScript。
3. 当前前端已经是无框架原生 DOM、Fetch、XMLHttpRequest 和 CSS，重构重点是拆文件与冻结行为，不是重新设计产品。
4. 当前仓库没有 web、templates 或 static 目录，也没有图片、字体、SVG、favicon 或独立脚本资源。
5. 当前网页没有前端编译步骤；目标也不应增加前端编译步骤。
6. 当前页面与 REST 服务同源，并依赖浏览器自动发送 Basic Auth；不得改成跨域调用 WPS。

## 5. 当前 JavaScript 状态模型

### 5.1 全局页面状态

当前状态对象位于 src/wps_adapter/web.py:318，字段含义如下：

| 字段 | 初始值 | 含义 | 更新位置 |
| --- | --- | --- | --- |
| path | / | 当前远端目录 | load |
| entries | 空数组 | 当前目录的完整条目集合 | load |
| busy | false | 是否有一个阻塞式前端操作在执行 | setBusy |
| search | 空字符串 | 当前目录本地搜索词 | 搜索输入事件 |
| connection | checking | 当前 WPS 连接状态 | setConnection |

另有三个独立变量：

1. rootName：当前云盘显示名称。
2. modalResolve：等待当前对话框结果的 Promise 回调。
3. modalMode：当前对话框是输入模式还是确认模式。

目录预取使用独立于 `state.entries` 的浏览器内存状态：`directoryCache` 按规范化路径保存 `entries`、过期时间和 pending Promise；`directoryCacheEpoch` 使失效前发出的请求结果作废；`prefetchQueue`、`prefetchActive` 和 `prefetchGeneration` 管理后台队列；`navigationGeneration` 防止旧目录请求覆盖当前页面。固定参数为 `DIRECTORY_CACHE_TTL_MS = 30 * 1000`、`PREFETCH_CONCURRENCY = 2` 和 `PREFETCH_MAX_FOLDERS = 24`。

### 5.2 连接状态

| 状态 | 页面文案 | 视觉类别 | 是否允许文件写操作 |
| --- | --- | --- | --- |
| checking | 正在检查 WPS | 警告色 | 否 |
| connected | WPS 已连接 | 成功色 | 是 |
| not_configured | WPS 尚未连接 | 失败色 | 否 |
| session_expired | WPS 登录已过期 | 失败色 | 否 |
| permission_denied | 无权访问当前工作区 | 失败色 | 否 |
| upstream_unavailable | WPS 暂时不可用 | 中性色 | 否 |
| invalid_response | WPS 响应异常 | 中性色 | 否 |
| unknown | WPS 状态未知 | 中性色 | 否 |

连接状态映射位于 src/wps_adapter/web.py:395。迁移时必须保留状态名，不能只保留“在线/离线”两个布尔值。

### 5.3 忙碌规则

1. 当前页面使用一个全局 busy 标记串行化用户操作。
2. busy 为 true 时关闭拖放遮罩。
3. busy 时设置按钮不可用。
4. WPS 未连接时，返回上级、上传、新建和条目操作不可用。
5. 设置名称按钮即使 WPS 未连接也可用，因为它只写本机设置。
6. 刷新按钮即使 WPS 未连接也可用，用于重新检查状态。
7. 第一轮不得擅自改成多个并行操作队列。

## 6. 当前前端调用的 HTTP 接口

### 6.1 请求总表

| 用户动作 | 方法与路径 | 查询参数 | 请求体 | 成功结果 |
| --- | --- | --- | --- | --- |
| 检查 WPS | GET /api/v1/status | 无 | 无 | 状态对象 |
| 读取目录 | GET /api/v1/entries | path | 无 | path 和 entries |
| 下载文件 | GET /api/v1/download | path | 无 | 文件流 |
| 读取名称，目标新增调用 | GET /api/v1/settings | 无 | 无 | status 和 name |
| 修改名称 | PATCH /api/v1/settings | 无 | 只含 name 的 JSON | status 和 name |
| 新建文件夹 | POST /api/v1/folders | path | 空请求体 | 新条目 |
| 重命名 | PATCH /api/v1/entries | path | 只含 name 的 JSON | 新路径和条目 |
| 移动 | PATCH /api/v1/entries | path | 只含 parent_path 的 JSON | 新路径和条目 |
| 删除 | DELETE /api/v1/entries | path | 空请求体 | 204 空响应 |
| 上传 | PUT /api/v1/upload | path，可选 overwrite=true | 原始文件字节 | 201 和条目 |
| 后台预取直接子目录 | GET /api/v1/entries | 每个直接子文件夹的 path | 无 | 仅写入浏览器目录缓存，不改变当前页面 |

### 6.2 统一请求规则

1. 所有请求都使用同源绝对 URL。
2. path 必须通过 URLSearchParams 编码，禁止字符串手工拼接查询参数。
3. Fetch 请求使用 no-store。
4. Fetch 和 XMLHttpRequest 都允许同源凭据。
5. JSON 写请求明确发送 application/json。
6. 上传发送文件 MIME；浏览器无类型时使用 application/octet-stream。
7. 错误响应先按文本读取，再尝试解析 JSON。
8. 若 JSON 有 error 字段，显示该字段。
9. 若 JSON 有 code 字段，保存在 Error 对象中供连接状态判断。
10. WPS 上游普通失败识别为 wps_unavailable。
11. WPS 会话过期识别为 wps_session_expired。
12. 非 JSON 错误退回“请求失败（状态码）”。
13. 不得在浏览器日志中输出响应正文、Basic Auth、Cookie、远端完整 URL 或文件内容。
14. `directoryCache` 是页面内存缓存，与 HTTP `no-store` 独立；不得把缓存内容持久化到 localStorage、sessionStorage 或 URL。
15. 预取失败必须丢弃对应缓存项，不得把失败转换为 `entries=[]`；用户真正打开该目录时仍需看到统一错误状态。

### 6.3 条目字段

前端当前消费以下字段；Go 响应必须保持字段名和类型：

| 字段 | 用途 |
| --- | --- |
| id | 身份信息，当前页面不直接展示 |
| name | 名称、路径拼接、搜索、对话框默认值 |
| kind | folder 或 file，决定打开或下载 |
| parent_id | 当前页面不展示，但属于兼容响应 |
| size | 文件大小显示 |
| modified_at | 以 Unix 秒转换为 zh-CN 本地时间 |
| etag | 当前页面不使用，但下载/WebDAV 契约使用 |

## 7. 当前用户流程的精确行为

### 7.1 初始加载

1. 页面建立初始状态。
2. 渲染根面包屑、根标题、路径和拖放目标。
3. 调用 load 读取根目录。
4. load 清空搜索词和搜索框。
5. load 先请求 status。
6. 只有 status 为 connected 才请求 entries。
7. 连接失败时清空 entries，并渲染对应空状态。
8. 目录成功时显示项目数和成功状态。
9. 初始页面本身不得因为 WPS 不可用而返回失败；页面壳必须仍能打开。
10. 当前目录成功后，按返回顺序安排最多 24 个直接子文件夹的后台预取，每次最多 2 个请求。
11. 预取请求不改变当前目录的 `entries`、搜索词、面包屑或状态文案。

### 7.2 面包屑、返回和刷新

1. 路径规范化为以斜杠开头、没有重复空组件的形式。
2. 根路径固定为单个斜杠。
3. 面包屑根名称使用可修改的 rootName。
4. 中间面包屑可点击，最后一个不可点击。
5. 返回上级从路径组件中删除最后一项。
6. 刷新重新执行 status 和 entries。
7. 进入任何目录时清空当前搜索。
8. 当前实现不把路径写入浏览器 URL，也不支持前进/后退历史；第一轮保持此行为。
9. 手动刷新强制重新读取当前目录，并替换预取队列 generation；不能直接使用该目录原有的 30 秒缓存。
10. 刷新时已经发出的旧请求可以自然结束，但其结果不能写回已失效缓存，也不能更新新的导航页面。

### 7.3 当前目录搜索

1. 搜索只针对已经加载的当前目录。
2. 搜索不向服务端发请求。
3. 搜索使用本地化小写转换后执行包含匹配。
4. 结果为空时区分“目录本身为空”和“没有匹配项目”。
5. 项目汇总同时显示匹配数和总数。
6. 搜索不得改变 entries 原数组。

### 7.4 打开与下载

1. 点击文件夹名称进入子目录。
2. 点击文件名称直接下载。
3. 文件操作区另有下载按钮。
4. 下载通过临时 a 元素触发，不先把文件读入浏览器内存。
5. download 属性使用原文件名。
6. 文件夹不显示下载按钮。
7. 点击文件夹时，如果该路径有未过期的预取缓存，直接使用缓存渲染；如果已有 pending 请求，复用该请求。

### 7.5 修改云盘显示名称

1. 点击齿轮打开输入对话框。
2. 对话框默认值为当前 rootName。
3. 取消、空字符串或未改变的名称不发送请求。
4. 提交时全页进入 busy。
5. 成功响应必须返回字符串 name。
6. 成功后更新 rootName、document.title、根面包屑、根目录标题和说明。
7. 该操作不依赖 WPS 连接状态。
8. 名称只影响适配器显示和虚拟根，不重命名 WPS 目录。

### 7.6 新建文件夹

1. 输入文件夹名称。
2. 空值或取消不发送请求。
3. 目标路径为当前路径与新名称的规范化拼接。
4. 提交期间进入 busy。
5. 成功后显示成功消息并强制刷新当前目录。
6. 错误使用统一错误展示。

### 7.7 重命名

1. 对话框初始值为现有名称。
2. 空值、取消或未变化不发送请求。
3. 请求目标 path 为原条目路径。
4. JSON 只发送 name。
5. 成功后刷新当前目录。

### 7.8 移动

1. 对话框输入的是目标父文件夹路径，不是完整目标文件路径。
2. 默认值为当前目录。
3. 输入值经过 canonicalPath。
4. JSON 使用 parent_path。
5. 成功后刷新原目录。
6. 跨空间限制由服务端决定，前端只展示服务端错误。

### 7.9 删除

1. 必须先显示含条目名称的确认对话框。
2. 文案明确说明操作会同步到 WPS。
3. 取消不发送请求。
4. 成功必须接受 204 空响应。
5. 成功后刷新当前目录。

### 7.10 上传

1. 文件选择器允许一次选多个文件。
2. 页面任意位置可接收文件拖放。
3. 忙碌或 WPS 未连接时不开始上传。
4. 多文件严格按选择顺序串行上传。
5. 每个文件目标为当前路径加文件名。
6. 若当前 entries 中存在同名文件：
   - 弹出覆盖确认。
   - 确认后增加 overwrite=true。
   - 取消后跳过该文件，继续下一个。
7. 若同名项目是文件夹，当前实现直接跳过，不弹错误。
8. 上传使用 XMLHttpRequest，因为 Fetch 当前不能可靠提供上传进度事件。
9. 每次 progress 计算百分比、平均速度、已传字节和总字节。
10. 上传期间显示进度条和速度。
11. 单个上传失败后停止本批次剩余上传。
12. 无论成功或失败，都隐藏进度和速度、退出 busy。
13. 成功完成整批后刷新当前目录。
14. 当前实现没有真正的“取消上传”按钮，也没有调用 XMLHttpRequest.abort。
15. 第一轮等价拆分不得声称已支持取消；若要新增取消功能，必须另开功能变更并补充契约和文档。

新建文件夹、重命名、移动、删除和每个成功上传都会清理网页目录缓存，并强制重新读取当前目录。清理同时丢弃尚未开始的预取队列；已经发出的请求不得把旧条目写回缓存。

### 7.11 拖放

1. 只响应 dataTransfer 中包含 Files 的事件。
2. dragenter 增加 dragDepth。
3. dragleave 减少 dragDepth，归零时隐藏遮罩。
4. dragover 阻止浏览器默认打开文件。
5. drop 阻止默认行为、清零 dragDepth、隐藏遮罩并启动上传。
6. busy 或未连接时不得显示可上传状态。

### 7.12 定时状态检查

1. 每 30 秒执行一次。
2. busy 时跳过本轮。
3. 静默请求 status。
4. 从 connected 变成非 connected 时清空目录并显示错误状态。
5. 从非 connected 恢复为 connected 时重新加载当前目录。
6. 页面销毁后浏览器自然停止计时器；当前没有额外生命周期框架。
7. 从非 connected 恢复为 connected 时先使网页目录缓存失效，避免新 WPS workspace 复用旧条目。
8. 状态检查和目录加载同时发生时，以最新 navigation generation 为准，旧响应不得恢复旧目录。

## 9. 目标文件与职责

### 9.1 web/index.html

1. 固定文档结构。
2. 语义标签与可访问性属性。
3. 固定的加载占位文案。
4. 指向同源 style.css 的 link。

禁止包含：

1. 内联 style。
2. 内联业务 script。
3. WPS Cookie、CSRF、工作区 ID 或 Basic Auth。
4. 由用户设置的根名称。

6. 外部 CDN。

### 9.2 web/style.css

只负责：

2. 布局和尺寸。
3. 按钮、输入框、表格、状态徽标、空状态、遮罩、dialog。

5. 720 像素移动端规则。
6. 可选的 prefers-reduced-motion 兼容；若加入，作为无行为变化的可访问性增强单独验证。

禁止：

1. 远端字体或图片引用。
2. 用 CSS 内容承载重要业务文本。
3. 为了视觉变化改动 DOM id。
4. 使用会遮挡操作区的绝对定位。

### 9.3 web/app.js

只负责：

1. 页面状态。
2. URL 和路径构造。
3. REST 请求与错误解析。
4. DOM 安全渲染。
5. 对话框流程。
6. 上传与进度。
7. 拖放。
8. 连接检查与轮询。
9. 30 秒目录缓存、直接子文件夹预取、最多 2 个并发请求、队列推进和失效 generation。

禁止：

1. 直接访问 WPS 域名。
2. 读取或保存 WPS Cookie。
3. 把服务端文本写入 innerHTML。
4. 把 Basic Auth 写入 localStorage、sessionStorage 或 URL。
5. 依赖全局第三方脚本。

### 9.4 web/embed.go

3. 确保只暴露清单中的资源。

禁止：

1. 包含业务路由。
2. 读取 WPS 配置。
3. 动态修改 index.html。
4. 提供任意磁盘文件路径。

1. 为第 15 节每个视口保存稳定截图。
2. 截图 fixture 使用固定名称、固定时间和固定文件大小。
3. 禁用动画或等待动画结束后再截图。
4. 不把 Basic Auth 弹窗纳入视觉快照。
5. 对关键区域增加位置断言，不能只依赖整图肉眼。
6. 检查页面宽高、表格滚动范围、dialog 边界和按钮边界不相交。
7. 任何截图更新都必须附带变化原因，不能用批量更新掩盖回归。

## 18. 前端性能验收

1. 页面只加载一个 HTML、一个 CSS 和一个 JavaScript。
2. 不加载外部字体、图标、分析脚本或 CDN。
3. 初次加载不重复请求 settings 或 status。
4. 搜索不重新渲染页面外无关区域。
5. 一万条目录上限场景不得让浏览器永久无响应；先记录 Python 页面基线，再决定是否需要分批渲染。
6. 不为了前端性能改变服务端目录条目顺序。
7. 上传文件正文不复制到 JavaScript 数组。
8. 下载不先调用 Fetch 把文件读入内存。
9. 轮询在 busy 时跳过，防止与写操作竞争。
10. 页面隐藏时是否暂停轮询属于后续优化，首版不得无测试改变。
11. 目录成功响应后预取调度必须限制为最多 24 个直接子文件夹和 2 个并发请求，不能因为宽目录创建无界 Promise。
12. 预取命中应避免重复的 WPS 列目录请求；缓存过期后必须恢复正常的单次请求流程。
13. 刷新、写操作和重新连接后的旧预取结果不得污染新目录；性能测试要同时记录命中、未命中和失效场景。

## 19. 测试门禁

每一阶段合并前必须全部满足：

1. 当前 Python 单元测试通过。
2. Go 前端资源 handler 测试通过。
3. 静态资源路径、MIME、认证、CSP 和 no-store 测试通过。
4. E2E 最小用例集通过。
5. 五个视口截图通过。
6. 浏览器控制台无未处理异常。
7. 浏览器网络面板无跨域请求。
8. 浏览器存储中无认证信息。
9. 页面响应和日志中无 WPS Cookie、CSRF、ID 或签名 URL。
10. Git 差异只包含本阶段预期文件。
11. 发布清单已经包含三个 web 文件。
12. 预取队列、缓存命中、TTL 过期和失效行为的 E2E 与网络请求计数测试通过。
13. 快速切换目录、刷新、重新连接和写操作期间没有旧响应覆盖当前页面。

## 20. 建议的原子提交顺序

执行模型一次只做一项，完成验证后再进入下一项：

1. 增加现状特征测试，不改页面。
2. 增加 E2E 假 storage 和最小页面加载用例。
3. 建立 web/index.html 的纯结构副本。
4. 提取 web/style.css。
5. Python 参照服务白名单提供 style.css。
6. 提取 web/app.js。
7. Python 参照服务白名单提供 app.js。
8. 修复或冻结 FE-01 到 FE-08 的负责人决定。
9. app.js 改为 GET settings 初始化根名称。
10. 删除 HTML 和 JavaScript 的动态名称注入。
11. 收紧 CSP。
12. 补齐全部桌面 E2E。
13. 补齐移动视口和截图。
14. 增加 Go 资源嵌入与 handler。
15. 对 Python/Go 运行同一套 E2E。
16. 灰度通过后删除 Python 内嵌模板。
17. 更新 API、架构、部署、README 和变更日志。
18. 重新生成发布清单并执行发布门禁。

## 21. 执行模型每一步的固定回报格式

每完成一个微步，必须报告：

1. 本步目标。
2. 实际修改的文件。

不得使用“前端已完成”这种笼统结论。只有第 19 节全部通过，才能声明前端等价迁移完成。

## 22. 最终完成定义

只有同时满足以下条件，才允许关闭前端迁移任务：

1. web/index.html、web/style.css、web/app.js 是唯一前端源文件。
2. 页面不含内联业务脚本或样式。
3. Go 二进制嵌入并提供这三个文件。
4. /、/web、/web/ 保持可用。
5. 页面和静态资源继续受 Basic Auth 保护。
6. 页面只调用同源 REST。
7. 所有现有浏览、搜索、上传、下载、新建、改名、移动、删除、设置和状态轮询行为通过 E2E。
8. 所有连接状态和错误状态通过 E2E。
9. 五个视口无重叠、溢出或不可达控件。
10. 根名称和文件名的恶意输入不会形成 HTML 或脚本。
11. CSP 不再依赖 unsafe-inline。
12. 无 Node.js 运行依赖或前端构建步骤。
13. Python 与 Go 对照期没有用户可见差异，已批准的安全修正除外。
14. 文档没有声称当前不存在的上传取消、前端路由或跨空间操作。
