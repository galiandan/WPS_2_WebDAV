# 上传并发、缓存与资源保护

> 功能编号：04
>
> 优先级：P1
>
> 状态：仅文档，暂不实现
>
> 更新时间：2026-09-04

## 1. 目标

在约 1.6 GiB 内存、可能没有 Swap 的 VPS 上，让多个 WebDAV、REST 和网页请求安全共存。重点保护内存、临时磁盘、WPS 请求配额和网络连接，避免大文件并发导致 OOM、磁盘耗尽或服务整体不可用。

本阶段不改变上传协议，只研究并定义限制、排队、取消、缓存和错误语义。

## 2. 当前基线

当前项目已经具备部分保护：

- 普通上传使用有限内存的临时 spool；
- 分片上传限制单片缓冲大小；
- 有上传/下载并发限制配置；
- 上传前检查临时空间保留量；
- 目录元数据使用短 TTL 缓存；
- 下载和上传都以流式方式处理，不把完整文件读入内存。

仍需要系统化确认：并发任务的总内存预算、缓存总量、磁盘预留、排队超时、客户端取消后的清理和服务重启后的临时文件清理。

## 3. OpenList 借鉴点

可借鉴 OpenList 的驱动层资源边界和流式传输思路：

- 由驱动统一管理远端对象和传输，而不是每个协议重复缓存；
- 对大文件使用分块/流式处理；
- 在传输前检查大小和可用资源；
- 通过并发限制保护后端和客户端；
- 将后端超时、限流和失败转换成稳定的上层错误。

OpenList 的具体缓存和并发参数属于 `external-reference`。本项目不会照搬可能依赖不同部署规格的默认值。

## 4. 需要验证的事实

| 事实 | 证据等级 | 研究要求 |
| --- | --- | --- |
| 当前上传临时 spool 的内存和磁盘行为 | `reproduced` | 补充不同文件大小和 `WPS_UPLOAD_SPOOL_MEMORY` 值的测试 |
| WPS 分片上传允许的并发程度 | `observed`/`candidate` | 在本人测试目录逐步增加并发，记录限流和失败 |
| WPS 上传会话和临时 URL 的过期时间 | `candidate` | 只测自己的上传任务，不重放他人 URL |
| WPS 下载对象是否支持并发 Range | `observed` | 使用本人测试文件验证，不把签名 URL 写入记录 |
| 缓存是否需要按群组和根目录隔离 | `inferred` | 增加切换工作区后的正确性测试 |

## 5. 实验步骤

1. 使用 1 MiB、50 MiB、100 MiB 和接近配置上限的测试文件，单独测上传内存峰值和临时磁盘峰值。
2. 同时启动 2、4、8 个上传和下载，观察服务内存、文件描述符、临时目录和 WPS 状态码。
3. 在等待、对象存储上传、merge 和文件登记阶段分别取消客户端请求，确认上游响应和本地临时文件都会关闭。
4. 在分片上传中断后检查临时目录和进程重启后的残留，不尝试未经确认的续传接口。
5. 遍历大量不同目录，测量缓存条目数量、总字节数和 TTL 到期后的回收行为。
6. 人为降低磁盘剩余空间，确认新上传被拒绝而已有下载和目录读取仍可用。

## 6. 设计方向

建议建立三类独立预算：

```text
内存预算：活动请求缓冲 + 分片缓冲 + 协议响应
磁盘预算：临时 spool + 保留空间 + 未完成任务
并发预算：上传、下载、WPS 控制请求分别限制
```

建议行为：

- 超过并发数时排队并设置有限等待时间，不无限堆积请求；
- 文件大小超过上限时在读取正文前拒绝；
- 磁盘低于保留阈值时拒绝需要 spool 的上传；
- 客户端断开时尽快关闭对象存储响应并释放预算；
- 缓存只保存元数据，不保存文件正文；
- 缓存键必须包含群组 ID、根目录和父目录；
- 服务启动时清理属于本项目且可安全识别的旧临时文件；
- 所有拒绝都返回明确的 429、413 或 507，而不是 502。

## 7. 验收标准

- 在配置的并发上限内，内存峰值有可解释上界；
- 超出并发上限时请求不会无限增长；
- 磁盘保留量不足时上传在读取大部分正文前失败；
- 取消和超时不会遗留持续占用的连接、文件或预算计数；
- 缓存不会跨群组或根目录返回错误条目；
- 目录缓存有条目数或总大小上限；
- VPS 重启后不需要人工删除危险残留文件；
- 资源不足时，健康检查和状态接口仍能响应；
- 不保存 Cookie、CSRF、refresh token、签名 URL 或文件正文。

## 8. 本阶段不实现

- 不引入 Redis、数据库或其他外部服务；
- 不默认开启无限并发或无限缓存；
- 不把整个文件长期保存到 VPS；
- 不根据未经验证的 WPS 限流猜测重试次数；
- 不在本阶段实现跨重启的分片续传，相关内容见 [`03-resumable-multipart.md`](03-resumable-multipart.md)。
