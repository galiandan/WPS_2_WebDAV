# 可恢复分片上传研究与实现计划

> 功能编号：03
>
> 状态：已实现基础检查点续传；WPS 远端列分片接口仍未确认
>
> 更新时间：2026-09-04

## 1. 目标

在当前 WPS 分片上传流程基础上，研究如何让大文件上传在网络中断、进程重启或单个分片失败后继续，而不必从第一个分片重新开始，同时保持 VPS 不长期保存文件的目标。

可恢复上传需要同时处理 WPS 对象存储上传会话、已完成分片，以及适配器本地对上传任务的最小进度记录。当前实现使用小型 JSON 检查点，不创建数据库，也不保存文件内容。

## 2. 当前实现基线

本人账号已经抓到并重放了 100 MiB、每片 10 MiB 的流程：

```text
POST /3rd/drive/api/v5/files/upload/block
  -> 获得 key、store、upload_id、分片限制
PUT /3rd/drive/api/v5/files/upload/block
  -> 获得指定分片的动态对象存储上传 URL
PUT <对象存储动态 URL>?partNumber=N&uploadId=...
  -> 上传分片并取得 ETag
POST /3rd/drive/api/v5/files/upload/block/merge
  -> 获得动态 complete URL 和 XML
POST <动态 complete URL>
  -> 合并对象存储分片
POST /3rd/drive/api/v5/files/file
  -> 登记 WPS 文件元数据
```

当前代码已经具备：

- 根据 WPS 返回的最小、最大分片限制选择分片大小；
- 使用分片 MD5 请求 WPS 获取分片上传指令；
- 按 WPS 返回的动态 URL 上传分片；
- 收集每个分片 ETag 并提交 merge；
- 对单个分片执行有限次数重试；
- 使用有限内存和临时 spool，避免把整个文件放进 Python 内存；
- merge 后登记文件。

当前代码通过本地检查点支持重新提交同一文件后的基础恢复；仍没有确认 WPS 是否提供列出已上传分片的接口、upload ID 生命周期和最终登记幂等性。

## 3. OpenList 借鉴点

OpenList 的 WPS 驱动和对象存储适配思路可借鉴：

- 以远端上传会话 ID、分片号和 ETag 作为进度核心；
- 分片上传 URL 必须由控制接口动态返回，不能写死签名 URL；
- 单片失败只重试该片；
- 合并请求按服务端返回的 ETag 和分片号生成；
- 控制面请求与对象存储数据面请求分开处理；
- 大文件操作需要大小、超时、并发和临时空间保护。

OpenList 的具体恢复接口、缓存方式和参数不代表 WPS 企业账号的真实行为，属于 `external-reference` / `candidate`。本项目优先遵守本人账号抓包，不复制外部项目的凭据管理或长期缓存设计。

## 4. 证据等级

| 结论 | 等级 | 说明 |
| --- | --- | --- |
| 分片初始化接口和 upload ID | `observed` + `reproduced` | 本人账号 100 MiB 上传抓包和当前测试 |
| 动态分片 URL、Content-MD5 和 ETag | `observed` + `reproduced` | 本人账号对象存储请求已验证 |
| block/merge 通过 XML 完成对象存储合并 | `observed` + `reproduced` | 本人账号抓包已确认 |
| 当前代码对单片失败有限重试 | `reproduced` | 已有实现和测试 |
| WPS 支持查询 upload ID 已完成分片 | `candidate` | 需要本人账号新 HAR 或实验确认 |
| upload ID 可跨进程、跨重启继续 | `unsupported` | 生命周期和权限尚未确认 |
| merge 或登记可安全重试且不重复建文件 | `unsupported` | 需要覆盖场景实验 |

## 5. 本人账号抓包和实验步骤

### 5.1 准备可校验的大文件

在本地生成一个非隐私、可重复生成的 100 MiB 测试文件。记录文件大小、MD5、SHA-1、SHA-256 以及每个 10 MiB 分片的 MD5。文件只用于本人测试，不上传到仓库。

### 5.2 抓取完整上传

1. 打开 WPS 网页端 Network，筛选 Fetch/XHR 并启用 Preserve log。
2. 上传测试文件到本人测试目录。
3. 记录初始化、每个分片、merge、文件登记的顺序。
4. 保存响应中的字段类型、`upload_id`、key、分片限制、ETag 关系和终态。
5. 立即导出并脱敏 HAR。

保留结构即可，不保留 Cookie、CSRF、refresh token、对象存储签名 URL、`AccessKeyId`、`Policy`、`Signature` 或原始文件内容。

### 5.3 制造中断

在测试目录中重复上传时，分别在初始化后、完成 1 个分片后、完成若干分片后、所有分片完成但 merge 前，以及 merge 完成但登记前停止。记录网页是否自动重试、是否重新初始化 upload ID，以及刷新页面后是否出现残留临时对象。

### 5.4 查找恢复线索

在中断后观察网页是否发起查询 upload ID、列出已完成分片、重新获取指定分片 URL、取消或清理未完成上传、重新提交 merge，或通过相同 key/SHA-1 恢复。只有本人账号抓包看到并成功重放的接口，才能进入候选实现，不能根据对象存储厂商的一般 API 猜测 WPS 控制接口。

### 5.5 恢复验证

对同一个测试文件中断并记录进度，重启适配器，使用同一任务信息恢复，只上传缺失分片，完成 merge 和文件登记，最后下载并校验完整文件哈希。如果恢复要求源文件重新读取，必须明确要求客户端支持可寻址读取，不把全部分片长期保存在 VPS。

## 6. 计划中的实现方案

只有在 upload ID 生命周期、分片查询和登记幂等性都得到本人账号证据后，才考虑实现以下方案。

### 6.1 最小任务记录

本地只保存恢复所必需的元数据，并使用原子写入和严格权限：

```json
{
  "task_id": "local-id",
  "group_id": "...",
  "parent_id": "...",
  "name": "...",
  "size": 0,
  "sha1": "...",
  "key": "...",
  "store": "...",
  "upload_id": "...",
  "parts": [{"part_number": 1, "etag": "..."}]
}
```

这只是研究中的数据边界，不表示当前要新增该格式。任务文件中不得保存 Cookie、CSRF 或签名 URL。

### 6.2 恢复规则

- 恢复前验证本地源文件大小和哈希仍匹配；
- 若能力已被本人账号确认，先向 WPS 查询远端已完成分片；
- 仅上传缺失或校验不一致的分片；
- 分片号与 ETag 一一对应；
- merge 使用按编号排序的完整分片清单；
- merge 成功后再登记文件；
- 文件登记使用明确的幂等策略，避免重启后重复创建；
- 无法确认远端状态时中止或新建任务，不盲目重放 merge。

### 6.3 资源保护

限制同时恢复的任务数、单任务和全局临时磁盘空间，复用现有超时和分片重试配置，任务过期后清理本地元数据。签名 URL 过期后重新向 WPS 获取，不持久化旧 URL。

## 7. 验收标准

- 100 MiB 测试文件按 WPS 返回的分片限制完整上传；
- 单分片网络失败只重试该分片；
- 进程重启后能恢复，或明确判断不能恢复并安全重新开始；
- 恢复不会重复上传已确认完成的分片；
- merge 后下载内容大小和 SHA-256 与源文件一致；
- 文件登记重试不会产生重复文件；
- upload ID 过期、凭据失效、空间不足和源文件改变时有清晰错误；
- 任务状态文件不包含 Cookie、CSRF、refresh token 或签名 URL；
- 并发任务不会突破内存、磁盘和上传并发限制；
- 未完成临时对象不会被误显示为正常文件。

## 8. 风险

- upload ID 可能很快过期或绑定原浏览器会话；
- WPS 可能不提供列分片和取消接口；
- 只保存元数据时，恢复仍要求客户端能重新提供源文件；
- 最终登记接口可能不是幂等的；
- 失败任务和远端残留分片可能只能由 WPS 回收；
- 任务状态文件包含文件名、ID 和哈希，也必须限制权限；
- 低内存 VPS 同时执行多个大文件任务仍可能资源耗尽。

## 9. 当前实现边界

- 配置 `WPS_UPLOAD_RESUME_DIR` 后启用持久化检查点；默认部署目录为 `/var/lib/wps-adapter/uploads`。
- 检查点只保存上传会话元数据和已完成分片 ETag，不保存 Cookie、CSRF、签名 URL 或文件内容。
- 重启后客户端必须重新提供同一个文件；适配器不会凭空恢复已断开的 HTTP 请求。
- 每完成一个分片会原子更新检查点；文件登记成功后删除检查点。
- WPS 远端列分片、取消上传、upload ID 续期和严格幂等登记仍未确认；旧会话失效时会明确失败，当前不会猜测恢复接口。

## 10. 本阶段明确不实现

- 不凭 OpenList 或对象存储通用文档猜测 WPS 恢复接口；
- 不新增任务数据库、后台队列或常驻上传管理器；
- 不把完整文件长期存储在 VPS；
- 不持久化对象存储签名 URL、Cookie 或 CSRF；
- 不实现未经抓包确认的列分片、取消、续期和幂等登记接口；
- 不改变当前已验证的分片上传、单片重试和资源保护逻辑；
