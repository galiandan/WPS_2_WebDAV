# 大目录与 Depth: infinity 研究与实现计划

> 功能编号：02
>
> 状态：已完成分页异常保护、递归循环保护、客户端断开取消和目录缓存上限；流式 PROPFIND 响应仍待后续优化
>
> 更新时间：2026-09-04

## 1. 目标

研究大目录分页、目录变化和 WebDAV `PROPFIND: Depth: infinity` 的兼容边界，使 Windows、NAS、Nextcloud 和同步软件可以稳定浏览目录，同时避免递归遍历耗尽 VPS 的内存、CPU、网络或 WPS 请求配额。

这里的“支持 infinity”不是无条件读取任意大小的整个云盘，而是在明确的递归深度、条目数、响应大小和请求时间预算内提供可预测结果。

## 2. 当前实现基线

当前客户端已使用本人账号验证过的目录接口：

```text
GET /3rd/drive/api/v5/groups/<group_id>/files
    ?parentid=<parent_id>&offset=<offset>&count=<count>
    &orderby=mtime&order=desc
```

当前适配器已有以下相关行为：

- 通过父目录 ID 获取子项；
- 用短 TTL 元数据缓存减少重复列目录请求；
- 对单次列表数量和 COPY 递归规模有上限；
- 目录元数据缓存有总目录数上限，超限淘汰最早过期项；
- WebDAV `PROPFIND` 可处理 `Depth: 0`、`1` 和 `infinity` 的受限逻辑；
- `max_copy_depth`、`max_copy_entries` 和 `WPS_MAX_LIST_ENTRIES` 等限制用于保护资源。

当前目录缓存是按父目录 ID 建立的进程内元数据缓存，不能当作持久化目录数据库。群组切换、缓存总量和分页一致性仍是重点风险。

当前已补充：分页遇到重复文件 ID 会明确失败；`Depth: infinity` 遍历遇到重复 ID 会停止，避免异常上游数据造成重复结果或循环。
客户端连接关闭后，递归会在进入下一项前停止；响应写出阶段也会释放下载流。目录缓存默认最多保留 1024 个父目录页面。

## 3. OpenList 借鉴点

OpenList 可借鉴的重点是驱动层对象模型和大目录处理思路：

- 把远端对象统一成名称、类型、大小、修改时间和 ID；
- 将分页读取隐藏在列目录抽象之后；
- 递归操作设置最大深度和数量保护；
- 将远端错误转换为上层协议可以理解的错误；
- 不把一次 API 返回的有限页面误当成完整目录。

OpenList 的具体分页参数、游标和 WPS 驱动实现属于 `external-reference`。只有当前账号 HAR 能确认的请求才可标记为 `observed`，重放并有自动化测试后才可标记为 `reproduced`。

## 4. 证据等级

| 结论 | 等级 | 说明 |
| --- | --- | --- |
| v5 `groups/<id>/files` 列目录接口 | `observed` + `reproduced` | 本人账号已有请求和项目实现 |
| `offset`、`count`、排序参数出现在网页请求中 | `observed` | 大目录一致性尚未系统验证 |
| WebDAV Depth 0/1/infinity 是客户端可能发送的值 | `external-reference` + 协议要求 | 来自 WebDAV 场景和现有测试 |
| 当前实现对 infinity 有受限处理 | `reproduced` | 有 WebDAV 测试，但不是无限制语义 |
| WPS 提供稳定游标或事件增量接口 | `candidate` | OpenList/外部资料线索，当前账号未确认 |
| 任意大目录可一次性完整返回 | `unsupported` | 不应假设，且与资源保护冲突 |

## 5. 本人账号抓包和实验步骤

### 5.1 准备隔离目录树

在本人企业空间建立 `adapter-depth-probe-20260904/`，准备空目录、两层子目录树、包含多个文件的目录，并在账号允许时建立超过网页默认显示数量的条目。不要使用隐私文件。

### 5.2 观察网页分页

1. 打开 Network，筛选 Fetch/XHR 并启用 Preserve log。
2. 进入测试目录，记录首次目录请求。
3. 翻页、滚动或切换排序，记录 `offset`、`count`、游标和排序字段的变化。
4. 进入子目录并返回，观察是否重新请求或使用缓存。
5. 只导出本轮 HAR，并立即脱敏。

### 5.3 观察递归读取

网页端不一定直接发送 WebDAV `Depth`，因此还要从适配器侧测试：

1. 对测试目录发送 `PROPFIND`，分别使用 `Depth: 0` 和 `Depth: 1`。
2. 再发送 `Depth: infinity`，记录适配器向 WPS 发起的请求数量、顺序和终止条件。
3. 使用不同目录深度和条目数量重复测试。
4. 中途断开客户端，确认适配器是否停止继续请求。

### 5.4 重放和一致性实验

先读取第一页，再新增或删除一个条目，然后读取下一页，记录是否重复、遗漏、排序漂移，以及 `next_offset` 或其他终止字段的表达。每次只改变一个变量，不能把 Cookie、签名 URL 或文件内容放入命令历史、日志或仓库。

## 6. 计划中的实现方案

### 6.1 分页层

- 每次请求使用不超过配置上限的 `count`；
- 只有响应明确表示还有下一页时才继续；
- 对 offset 不前进、重复 ID 或异常大响应设置保护；
- 在一个 WebDAV 请求内设置总条目数、响应字节数和截止时间预算；
- 同一目录分页期间固定排序参数。

如果 WPS 提供真实游标，应先单独验证游标生命周期和失效行为，再替换 offset，不同时混用两种机制。

### 6.2 Depth 层

| Depth | 行为 |
| --- | --- |
| `0` | 只返回请求资源属性 |
| `1` | 返回请求资源和直接子项 |
| `infinity` | 递归读取，但受深度、条目、响应大小和时间上限约束 |

`infinity` 应使用迭代队列或受控递归，逐目录读取，不缓存文件正文；发现循环或异常路径立即终止；达到任一预算时返回明确限制错误；客户端断开后尽快停止后续 WPS 请求。

### 6.3 缓存层

缓存只保存短期元数据，不保存文件正文。实现前必须确定：

- 缓存键包含 group ID、parent ID 和必要的工作区版本信息；
- 上传、删除、移动、重命名后正确失效；
- TTL 过期项和缓存总量有上限；
- 并发请求不会无限扩张缓存；
- WPS 不可用时不会把过期数据伪装成实时成功结果。

### 6.4 XML 响应

WebDAV XML 必须转义文件名和路径，校验大小与修改时间，执行响应大小预算，并且不写入 Cookie、CSRF、签名 URL 或内部用户资料。

## 7. 验收标准

- 空目录、单页目录、多页目录正确列出；
- 分页不会因 offset 不前进而死循环；
- Depth 0、1 的 XML 结果符合协议预期；
- infinity 在限制范围内遍历完整测试树；
- 超出深度、条目、响应大小或时间限制时返回稳定错误；
- 特殊字符名称不会破坏 XML；
- 变更后不会长时间返回旧目录；
- 群组切换后不会复用其他群组缓存；
- WPS 401、403、网络故障不会被伪装成空目录；
- 客户端断开后停止无意义遍历；
- 覆盖空页、重复 ID、异常 JSON、短读和上游超时测试。

## 8. 风险

- 网页分页请求不一定是稳定契约；
- offset 分页期间目录变化可能造成重复或遗漏；
- infinity 会把一次请求放大为大量 WPS 请求；
- XML 响应可能占用大量内存和带宽；
- 子目录权限可能不同；
- 短 TTL 造成重复请求，长 TTL 造成旧数据；
- 某些客户端将 infinity 理解为无界递归，必须保留保护上限。

## 9. 当前实现边界

- `offset` 分页继续使用 WPS 已观察到的 `next_offset`；不会猜测游标接口。
- 单次目录和递归响应仍受条目、深度和 XML 响应大小限制。
- 当前 PROPFIND 仍会先构造受限的元数据结果，再发送 XML；真正的流式 XML 仍未实现。

## 10. 本阶段明确不实现

- 不承诺无上限的 `Depth: infinity`；
- 不凭 OpenList 猜测 WPS 游标、事件或分页字段；
- 不建立完整云盘本地索引；
- 不把文件正文写入目录缓存；
- 不实现跨群组目录合并；
- 不为了兼容客户端取消资源保护。
