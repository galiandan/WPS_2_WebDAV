# 重复文件处理策略

> 文档类型：OpenList 借鉴方向之五
>
> 状态：研究与设计，尚未实现
>
> 更新时间：2026-09-04

## 1. 目标与优先级

重复文件处理是本项目后续优先级第五的功能。它的目标不是简单地把所有同名上传都改成覆盖，而是让 REST、WebDAV、网页上传和不同客户端对“目标已经存在”有一致、可预测且不会误删数据的行为。

当前建议的整体优先级为：

| 优先级 | 功能 | 本文档状态 |
| --- | --- | --- |
| 1 | WPS 原生 COPY 或低成本复制路径 | 待实验确认 |
| 2 | 大目录分页、`Depth: infinity` 限制和稳定性 | 部分已有设计，待完善 |
| 3 | 分片上传失败重试与断点恢复 | 分片流程已复现，恢复仍待验证 |
| 4 | 上传并发、缓存和资源保护 | 部分已有设计，待完善 |
| 5 | 重复文件处理策略 | 本文档；尚未实现 |

本文档只设计第 5 项，不修改现有的上传覆盖行为。当前已验证的同名覆盖流程应继续保留，直到新策略完成实验、实现和回归测试。

## 2. 需要解决的问题

WPS 网页端和 WebDAV 客户端对同名文件的预期可能不同：

- 网页上传通常允许用户选择覆盖或生成新文件；
- WebDAV `PUT` 常被客户端视为“写入这个路径”，通常期望替换已有文件；
- 同步软件可能需要跳过、冲突重命名或保留双方版本；
- `COPY` 的目标已存在时，客户端通常期望明确的冲突状态，而不是静默覆盖；
- WPS 的控制接口可能分别提供预检查、更新和新建路径，不能只根据 HTTP 状态推断语义。

适配器必须先在本地决定策略，再调用 WPS。不能先删除目标、再上传源文件来模拟覆盖，因为中途失败会造成数据丢失。

## 3. OpenList 借鉴点

OpenList 可借鉴的重点是“驱动层能力”和“上层冲突策略分离”，包括：

- 在统一文件对象模型中区分文件、目录、ID、父目录和名称；
- 在复制、移动和上传前进行目标存在性检查；
- 把覆盖、跳过和自动改名作为显式策略，而不是散落在每个协议处理器中；
- 对不支持原子操作的后端，通过明确的错误和限制保护调用方；
- 将驱动返回的错误转换为上层可识别的冲突错误。

OpenList 的具体 WPS 请求、参数名和冲突字段只能作为 `external-reference` 或 `candidate`。不能因为 OpenList 对某个版本的 WPS 做了处理，就认定当前企业账号支持相同接口。

## 4. 证据边界

| 内容 | 证据等级 | 当前结论 |
| --- | --- | --- |
| WPS 普通上传 `create_update` 后登记文件 | `observed` + `reproduced` | 本人账号已验证，可继续作为上传基础 |
| 现有 REST `overwrite=true` 覆盖同名文件 | `reproduced` | 已验证保持文件 ID 并得到新内容 |
| 当前项目拒绝或限制部分目标覆盖 | `current-design` | 以代码和 WebDAV 文档为准，不代表 WPS 原子保证 |
| OpenList 的目标存在检查和冲突策略思路 | `external-reference` | 只能形成设计假设 |
| OpenList/WPS 的具体冲突参数或批量复制字段 | `candidate` | 必须用本人账号抓包后单独验证 |
| WPS 是否提供原子“新建且不覆盖”接口 | `unknown` | 不得凭空承诺 |
| WPS 是否支持服务端原子覆盖和版本回滚 | `unknown` | 需抓包、故障实验和结果确认 |

研究记录必须写入脱敏后的实验编号、时间、测试目录和响应摘要。不得提交 Cookie、CSRF、refresh token、签名对象 URL、原始 HAR 或真实文件内容。

## 5. 实验步骤

所有实验只使用本人账号、专用测试目录和可删除的测试文件。文件名应带日期和策略，例如 `duplicate-policy-YYYYMMDD`。

### 5.1 建立基线

1. 在测试目录创建 `source.txt`，记录其文件 ID、大小、哈希和版本号。
2. 创建同名目标或上传第二个同名文件，记录 WPS 网页端的提示和最终目录结果。
3. 分别记录网页端“覆盖”“另存为/重命名”“取消”三种行为对应的请求。
4. 对每个请求只保留脱敏后的方法、路径、参数名、响应字段和任务 ID。

### 5.2 验证 REST 上传策略

分别测试：

- 目标不存在；
- 目标存在且 `overwrite=false`；
- 目标存在且 `overwrite=true`；
- 目标是目录而上传路径是文件；
- 目标文件正在被另一个操作修改；
- 上传对象成功但最终文件登记失败。

每次实验都要确认：目标文件 ID 是否保持、版本号是否变化、旧内容是否仍可通过 WPS 版本历史恢复，以及失败后目录中是否留下孤儿对象或半成品。

### 5.3 验证 WebDAV 语义

使用 `PUT`、`COPY` 和网页上传分别测试同名目标。至少记录：

- 没有 `Overwrite` 请求头时的默认行为；
- `Overwrite: T` 和 `Overwrite: F` 的行为；
- 目标存在时返回 `201`、`204`、`409` 或 `412` 的映射；
- 目标为目录、源为目录和跨目录复制的行为；
- 中途断开后目标是否可见；
- 客户端重试同一个请求时是否产生多个文件。

### 5.4 故障与并发实验

在小文件测试中模拟对象上传成功、WPS 登记失败、网络超时和重复请求。再用两个串行或受限并发请求写入同一路径，观察 WPS 是否提供版本冲突、条件请求或最后写入者胜出的语义。

在没有确认原子性前，适配器不能通过先删除旧文件来实现覆盖，也不能把“最后一次请求成功”宣传为事务保证。

## 6. 协议设计

### 6.1 内部策略模型

冲突策略应在存储层统一表达，建议使用以下枚举语义：

```text
fail       目标存在即失败，保护已有数据
overwrite  在 WPS 已确认支持的更新路径上覆盖
skip       目标存在时不上传，返回已有目标信息
rename     自动生成不冲突的新名称后创建
```

默认值建议为 `fail`，但必须保留现有 WebDAV `PUT` 的兼容行为，并通过单独的协议映射决定默认值。不能在一次升级中悄悄改变用户现有的覆盖语义。

### 6.2 REST API

REST 上传可继续使用现有的：

```text
PUT /api/v1/upload?path=/目录/文件名&overwrite=true|false
```

后续如增加策略参数，优先使用明确的 `conflict` 字段，例如 `fail`、`overwrite`、`skip` 或 `rename`，并规定 `overwrite` 与 `conflict` 同时出现时的优先级。未知值必须返回 `400`，不能静默采用覆盖。

建议响应至少包含：

```json
{
  "path": "/目录/文件名",
  "entry": {},
  "created": false,
  "conflict": "overwrite"
}
```

真实响应字段需在实现前确定，本文示例不是已承诺的 API。

### 6.3 WebDAV `PUT`

WebDAV `PUT` 需要遵循客户端发送的 `Overwrite` 或项目定义的默认策略：

- `Overwrite: F` 且目标存在：返回 `412 Precondition Failed`；
- 目标不存在并成功创建：返回 `201 Created`；
- 明确覆盖并成功更新：返回 `204 No Content` 或项目已经稳定使用的成功状态；
- 同名但类型冲突：返回 `409 Conflict`；
- 策略不允许覆盖：不得删除目标后重试。

这些状态码是 WebDAV 适配设计，不能反推 WPS 底层一定使用相同语义。

### 6.4 WebDAV `COPY`

`COPY` 的默认建议是 `Overwrite: F`，除非客户端明确发送 `Overwrite: T`。对于尚未验证覆盖语义的 WPS 原生 COPY，适配器必须对中继复制施加：

- 源和目标解析后再次检查目标；
- 不覆盖时发现目标立即返回冲突；
- 覆盖时不先删除目标；
- 大文件复制使用受限流式中继和上传限制；
- 失败后清理适配器已创建的临时状态，但不误删原目标。

目录 COPY 是否递归、同名子项如何处理以及失败后的部分目录如何表示，必须在原生接口或本地事务策略确认后再开放。

### 6.5 自动重命名

自动重命名必须是确定、可重试且不覆盖的。例如：

```text
report.txt
report (1).txt
report (2).txt
```

名称生成必须保留扩展名、限制长度、拒绝控制字符，并在最终创建前重新检查冲突。并发下若创建失败，必须重新读取目录并生成下一个名称，不能假定序号唯一。

## 7. 验收标准

功能只有满足以下条件后才能实现并进入默认发布：

1. REST、WebDAV、网页上传的冲突结果和文档一致。
2. 默认策略不会覆盖已有文件，除非现有兼容约定或用户明确请求覆盖。
3. `Overwrite: F` 在目标存在时稳定返回 `412`，且旧文件内容、ID 和版本不变。
4. 明确覆盖不会先删除目标；上传或登记失败时旧文件仍可访问，或有已验证的 WPS 版本恢复路径。
5. `skip` 不产生新对象、不修改文件版本，并返回已有条目。
6. `rename` 在串行和受限并发下都不会覆盖其他文件。
7. 文件与目录类型冲突返回明确的 `409`，不会触发错误的上传或删除。
8. 客户端重复提交同一请求不会无界地产生副本。
9. 大文件策略受 VPS 内存、临时空间和并发限制保护。
10. 单元测试覆盖不存在、存在、权限失败、网络失败、登记失败和重试场景；真实 WPS 验收使用专用测试目录。

## 8. 风险与隐私要求

- WPS 的“更新文件”可能是新版本登记，不一定是原子替换；适配器必须如实说明。
- 文件名可能包含隐私信息，日志只记录脱敏路径或必要的短 ID。
- 不把冲突策略、文件名、用户输入拼接进 Shell 命令。
- 不把 WPS Cookie、CSRF、签名 URL 或对象存储凭据放入响应、日志、错误详情或任务状态。
- 失败的对象存储上传可能留下云端未登记对象，必须研究清理接口或设置可接受的孤儿对象风险。
- 自动重命名会影响同步软件判断，策略和命名规则必须版本化并写入文档。
- 任何来自 OpenList 的未验证接口只允许在本人测试目录中显式启用，不能作为默认回退。
