# 原生 COPY 研究与实现计划

> 功能编号：01
>
> 状态：已实现同空间单文件原生 COPY；文件夹、覆盖和跨空间语义仍未确认
>
> 更新时间：2026-09-04

## 1. 目标

记录已确认的 WPS 服务端复制能力，并继续验证文件夹复制和覆盖语义。

目标是让同一 WPS 空间内的文件复制尽量不经过 VPS 文件内容中继，从而降低 VPS 带宽、临时磁盘和内存压力。本功能只研究复制，不改变移动、删除、上传和下载的既有流程。

## 2. 当前实现基线

当前 `WpsStorage.copy_path()` 对已确认的单文件场景使用 WPS 原生复制，其他场景仍使用受限的中继复制：

```text
单文件：WPS 控制面复制 -> 返回新文件 ID
文件夹或未确认场景：解析源路径 -> WPS 流式下载 -> WPS 上传到目标目录
```

当前行为包括：

- 支持文件和文件夹复制；
- 支持 `Depth: 0`、`1`、`infinity`；
- 通过 `max_copy_entries` 和 `max_copy_depth` 限制递归规模；
- 不把整个文件读入单个 Python `bytes` 对象；
- 目标存在时不宣称原子覆盖，当前会拒绝有风险的 COPY 覆盖场景；
- 递归复制中途失败时，会尝试删除新建的目标根目录。

已确认的单文件请求为 `POST /3rd/drive/api/v3/groups/<groupid>/files/batch/copy`，请求使用 `fileids`、`groupid`、`target_groupid`、`target_parentid` 和 `duplicated_name_model=1`；WPS 返回新文件 ID 后才向 WebDAV 返回成功。

因此，“WebDAV COPY 能工作”和“WPS 原生 COPY 已确认”是两件不同的事。本阶段研究完成前，不删除中继实现。

## 3. OpenList 借鉴点

OpenList 的 WPS 驱动提供了批量复制接口的研究线索，候选请求形状为：

```text
POST /3rd/drive/api/v3/groups/<group_id>/files/batch/copy
```

可借鉴的是控制面任务模型，而不是某次请求中的具体 Cookie、Token 或固定参数：

- 由控制面 API 提交复制任务，而不是让适配器下载完整内容；
- 使用 WPS 文件 ID 和目标父目录 ID 表达对象关系；
- 对接口响应做严格字段检查；
- 如果 WPS 返回任务 ID，则轮询任务状态后再向 WebDAV 客户端报告成功；
- 保留原有中继方式作为能力不足或接口失败时的受控回退。

OpenList 资料目前只能标记为 `external-reference` / `candidate`。它没有证明该接口适用于本人的 `365.kdocs.cn` 企业账号，也没有证明字段、覆盖语义或目录递归语义稳定。

## 4. 证据等级

| 结论 | 等级 | 说明 |
| --- | --- | --- |
| 当前适配器支持 COPY 中继 | `reproduced` | 仓库已有实现和 WebDAV 测试 |
| WPS v5 文件列表、上传、下载和任务移动/删除 | `observed` + `reproduced` | 本人账号抓包并已用于当前实现 |
| `/3rd/drive/api/v3/groups/<id>/files/batch/copy` 存在 | `candidate` | 来自 OpenList，当前账号尚未确认 |
| 同空间单文件原生 COPY 的请求字段和响应结构 | `observed` + `reproduced` | 本人账号抓包并已加入客户端实现和测试 |
| 原生 COPY 的文件夹递归、覆盖和任务语义 | `unsupported` | 尚未通过实验确认 |

在没有新的本人账号 HAR 之前，不能把候选接口接入默认路径，也不能称其为 WPS 官方稳定 API。

## 5. 本人账号抓包步骤

### 5.1 准备测试目录

在 WPS 网页端创建专用测试目录，例如 `adapter-copy-probe-20260904/`，其中准备一个小文本文件、一个含文件的子目录和一个重复名称测试目标。所有对象必须属于本人有权操作的企业空间。

### 5.2 抓取网页端复制操作

1. 打开 Network，只保留 Fetch/XHR，勾选 Preserve log。
2. 清空旧请求，在网页中复制一个小文件到另一个测试目录。
3. 等待网页显示复制完成，再复制一个测试文件夹，观察是否出现任务轮询。
4. 只导出本轮操作的 HAR，不要导出全部浏览历史。

### 5.3 脱敏记录

只记录脱敏后的方法、主机、路径、参数名、JSON 字段类型、文件 ID 关系、状态码、任务 ID 和终态字段。必须删除 Cookie、CSRF、refresh token、`AccessKeyId`、`Signature`、`Policy`、对象存储临时 URL、文件内容和不必要的用户资料。

### 5.4 单请求重放

先重放单文件复制，确认目标新增文件；再测试文件夹复制、递归选项和同名目标。记录拒绝、覆盖、重命名或异步失败的真实行为。每次只改变一个变量，失败时停止，不尝试修改权限或绕过限制。

## 6. 计划中的实现方案

只有在抓包和最小重放都成功后，才考虑：

1. 在 `WpsDriveClient` 增加严格校验的原生复制方法。
2. 请求体只包含抓包确认过的字段，并使用当前工作区的 group ID、源文件 ID 和目标父目录 ID。
3. 如果响应返回任务 UUID，复用现有任务轮询和错误分类逻辑。
4. 完成后重新读取目标元数据，不直接拼造 WebDAV 属性。
5. 在 `WpsStorage.copy_path()` 中增加显式策略，原生复制成功才返回；未验证、能力不支持或响应异常时，按配置决定是否回退中继。
6. 默认回退必须有超时、条目数和深度限制，不能因原生接口失败而无限重试。

跨 group ID 复制暂不默认支持，除非本人账号抓包证明 WPS 允许且权限边界清楚。只有确认目标已经创建或任务成功完成后，才向 WebDAV 客户端返回成功。

## 7. 验收标准

- 单个小文件在同一 group 内原生复制成功；
- 源文件内容、名称和目标父目录正确；
- 文件夹复制的递归范围与 WPS 实际行为一致；
- 同名目标行为有记录并有测试；
- 异步任务失败时不返回成功，且错误不泄露凭据；
- 失败不会留下错误目标，或能明确报告残留并执行受限清理；
- 原生复制不可用时，当前中继 COPY 仍然可用；
- 大文件复制不一次性载入内存；
- 不同 group ID 不会误复制或越权；
- 单元测试不依赖真实账号、Cookie 或网络。

## 8. 风险

- OpenList 候选接口可能只适用于不同版本或类型的 WPS 空间；
- 一个复制动作可能由多个控制请求组成，不能只凭 URL 名称判断语义；
- 提交异步任务不等于复制完成；
- 覆盖可能不是原子操作，错误回退可能破坏已有目标；
- 文件夹递归受权限、数量和服务端限制影响；
- 任务重试可能产生重复文件，必须验证目标状态而非盲目重放。

## 9. 本阶段明确不实现

- 不凭 OpenList 代码扩展未经验证的原生 COPY 语义；
- 不扫描其他用户、租户或未授权 group；
- 不实现跨租户复制；
- 不实现未经抓包确认的文件夹、覆盖、重命名或冲突策略；
- 不删除当前中继 COPY；
- 不承诺 WPS 服务端原子事务语义；
- 不把对象存储临时 URL 暴露给 WebDAV 客户端；
- 不实现文件夹原生复制、覆盖复制或跨空间复制，直到获得对应真实抓包证据。
