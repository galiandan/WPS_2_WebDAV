# 企业空间与目录发现

> 文档类型：OpenList 借鉴方向之二
>
> 更新时间：2026-09-04

## 1. 目标

让用户登录后从本人账号可见的企业空间中选择目标空间，默认从该空间的根目录开始，而不是依赖浏览器恢复的旧页面目录或要求用户手抄长数字 ID。

```text
登录 -> 检查会话 -> 列出本人可见空间 -> 用户选择 -> 验证根目录 -> 保存工作区
```

这里的“空间”包括 WPS 返回给当前账号的群组/企业云盘上下文；程序不能扫描或猜测其他群组。

## 2. 证据边界

| 内容 | 证据级别 | 说明 |
| --- | --- | --- |
| `group_id`、`parent_id` 是当前文件列表和操作所需的上下文 | observed + reproduced | 来自本人账号网页请求、REST 回放和当前实现 |
| `parentid=0` 可作为选定群组的根目录入口 | observed/design baseline | 当前项目默认 `root_id=0`；仍需按账号验证根目录可读性 |
| `GET /3rd/plus/groups/v1/companies/<companyid>/users/self/groups/private` | candidate | 来自 OpenList Business 模式，当前账号未确认 |
| `companyid`、`current_companyid`、`is_company_account` | external-reference | 来自 OpenList 的 `islogin` 解析，不是当前项目的实测契约 |
| 企业接口失败后改用个人版接口且声称结果完整 | unsupported | OpenList 参考本身提示企业账号结果可能不完整 |

因此，企业空间自动发现功能在正式启用前必须用当前账号的新 HAR 观察并验证。现阶段已有的群组 ID 只能作为用户明确提供或登录助手当前上下文得到的配置，不能推导其他空间。

当前已完成不依赖猜测接口的第一阶段：登录助手从当前官方页面取得群组/目录上下文，默认使用根目录，并在同步前验证目标目录可读。自动列出多个企业空间仍未启用。

## 3. 当前项目基线

当前适配器保存最小工作区状态：

```json
{
  "group_id": "<selected-group-id>",
  "root_id": "0"
}
```

真正定位目录使用 ID，不使用目录显示名称。用户指定某个子目录时，保存该目录的 ID；登录后浏览器自动跳回其他目录时，不应把它误认为目标目录。

目录列表的本人账号观察请求为：

```text
GET /3rd/drive/api/v5/groups/<group-id>/files
    ?parentid=<parent-id>
    &offset=<offset>
    &count=<count>
    &orderby=mtime
    &order=desc
```

实际网页请求还带有 `linkgroup`、`include`、`with_link`、`review_pic_thumbnail` 和 `with_sharefolder_type` 等参数；当前不能断言它们全部必需。

## 4. 推荐交互

单个候选空间：

```text
发现 1 个可用企业空间：学校云盘
使用该空间并从根目录开始？ [Y/n]
```

多个候选空间：

```text
发现 2 个可用企业空间：
[1] 学校云盘
[2] 个人团队
请选择 [1]：
```

同名空间必须显示序号。已保存的空间仍在候选列表时，可默认保留原选择；如果已保存空间不再出现，必须要求重新选择，不能静默切换到另一个空间。

## 5. 发现和验证流程

```text
1. 读取当前账号的临时浏览器会话
2. 执行已确认的登录状态预检
3. 若当前账号上下文提供企业 ID，再尝试企业群组候选接口
4. 严格校验返回对象中的 ID 和显示名称
5. 让用户在返回的候选中选择
6. 使用 group_id + parentid=0 做最小目录读取
7. 若用户指定子目录，验证该目录可读后保存其 ID
8. 原子写入 wps-workspace.json
```

如果企业发现候选接口不存在、返回结构变化、返回空结果或权限不足，应明确报告“无法自动发现”，并允许用户使用官方页面上下文或显式配置回退。回退不能隐藏自动发现失败的事实。

## 6. 状态文件和安全要求

- `group_id` 是定位依据，`group_name` 如果未来保存只能用于展示；
- 企业 ID、用户 ID 没有必要写入工作区文件；
- 文件权限应为 0600，目录权限应为 0700；
- 写入采用临时文件、刷新和原子替换；
- 新选择验证成功后才替换旧状态；
- 更新失败应保留旧的有效工作区；
- 不保存 Cookie、CSRF、refresh token 或签名对象存储 URL。

## 7. 验收标准

1. 登录后默认从 `parentid=0` 开始，而不是从浏览器旧页面目录开始。
2. 多空间账号只显示接口返回且当前账号可见的候选。
3. 用户指定子目录时，保存并使用该目录 ID。
4. 无权或已失效的工作区显示明确错误，不自动换空间。
5. 企业发现候选接口未经当前账号验证时，产品文档和界面都标注其未确认状态。
