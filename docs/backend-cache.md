# 后端目录缓存优化（v1.0.24）

本轮优化聚焦 storage 层共用的目录元数据缓存，适用于网页文件列表与 WebDAV 路径解析。没有更改 WPS 请求格式，不需要新增配置或依赖，不访问真实 WPS 进行测试。

## 参考设计

查阅 OpenList 提交 `d894a3983b329eab456561937b6f3383f466f216`：

- [internal/op/fs.go](https://github.com/OpenListTeam/OpenList/blob/d894a3983b329eab456561937b6f3383f466f216/internal/op/fs.go)：先查目录缓存，再以 singleflight 合并同一目录的加载请求。
- [pkg/singleflight/singleflight.go](https://github.com/OpenListTeam/OpenList/blob/d894a3983b329eab456561937b6f3383f466f216/pkg/singleflight/singleflight.go)：Forget 解除后续请求与旧请求的绑定；完成请求仅在自身仍是当前记录时移除记录。

这里借鉴设计思路，未复制上游代码。项目原本已有目录请求合并，本次将其失效机制改为请求身份判断；淘汰堆使用 Go 标准库 container/heap 独立实现，并保留本项目的过期时间优先语义。

## 行为与边界

- 缓存键仍包含空间、根目录 generation 和父目录 ID。默认 TTL 仍为 2 秒，容量仍为 1024 个目录。
- 最小堆按到期时间排序，同到期时间按插入序号排序；读取不会延长 TTL。满容量插入、刷新和定向移除为 O(log n)，缓存查询仍为 O(1)。
- 目录失效同时删除缓存项和当前在途记录。旧请求继续向原调用方返回结果，但不能回填缓存、删除替代请求或覆盖新结果。
- 全量失效清空目录缓存、堆和在途索引，同时递增 generation；加载完成时还必须确认键属于当前 generation。
- 单目录失效在同一把锁下读取 generation，避免与全量失效产生数据竞争。不再保留随历史写入目录数量累积的 epoch 表；堆节点随缓存项一起移除。
- 原有调用方仍须将返回的缓存条目视为只读。此次没有新增请求取消传播、上游重试或后台刷新机制。

## 基准与验证

对比基线 `5c1a33c` 和本次实现，使用相同基准：预填满缓存，再循环访问容量加一的目录集合，使每次操作都触发淘汰。空目录加载器不包含网络耗时。在 Linux amd64、AMD Ryzen 7 9700X、Go 1.27.1 环境下，各运行三次、每次 300ms，取中位数：

| 目录容量 | 原实现 ns/op | 新实现 ns/op |
| --- | ---: | ---: |
| 128 | 1171 | 316.8 |
| 1024（默认） | 8064 | 363.3 |
| 8192 | 69052 | 413.4 |

默认容量下，此淘汰密集场景约快 22 倍。每次操作仍为 3 次分配，分配字节数从 240 B 增至 272 B，另有有界的堆索引空间。此结果只说明本地缓存维护成本，不代表真实 WPS 请求或端到端文件浏览有相同比例的改善。

复现命令（在 go/ 下）：

```sh
go test ./internal/cache -run '^$' -bench BenchmarkMetadataEviction -benchtime=300ms -count=3
go test -race ./...
```

新增回归覆盖失效前获取的旧键、两种失效方式下新旧请求的两种完成顺序、刷新后的淘汰顺序、反复定向失效后的索引大小，以及全量失效／定向失效／加载的并发交错。沿用既有的同目录请求合并、跨目录并行、错误不缓存、空目录缓存和过期淘汰测试。
