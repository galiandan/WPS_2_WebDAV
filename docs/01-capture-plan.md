# 第一阶段：网页端抓包方案

本阶段目标是回答四个问题：如何列目录、如何表示文件/文件夹、如何上传和下载，以及请求依赖什么认证上下文。只做小范围、低频、本人账号的操作。

## 准备

1. 在 WPS 网页端登录本人账号，确认可以手工打开企业云盘。
2. 在网盘中建立一个专用测试目录，例如 `adapter-probe-YYYYMMDD`。
3. 准备一个不含隐私的 4-16 KiB 文本文件，以及一个空目录名。先不要使用大文件。
4. 打开浏览器开发者工具的 Network 面板，勾选 Preserve log；优先观察 `fetch` / `xhr`，必要时再看 document、other 和跳转。
5. 每轮只做一个动作，并在记录中写下动作前后的 UI 状态。不要把复制出的带认证 cURL 直接发送或提交。

## 推荐记录顺序

可以为每个动作单独清空 Network 记录并导出 HAR；单独文件比混合整段登录流程更容易判断因果关系。

| 实验 | UI 动作 | 需要确认的内容 |
| --- | --- | --- |
| L-01 | 打开测试目录 | 列表请求的 method、路径、父目录参数、分页和响应结构 |
| L-02 | 进入子目录再返回 | 文件夹 ID 是否稳定，返回是否重新请求，是否有面包屑参数 |
| L-03 | 创建空文件夹 | 创建请求的 body、父目录字段和返回的目录对象 |
| U-01 | 上传 4-16 KiB 文件 | 是否先初始化，再直传或提交；文件 ID 何时产生 |
| U-02 | 上传本人生成的 100 MiB 测试文件 | 初始化、分片大小、每片校验、合并 XML 和最终登记顺序 |
| O-01 | 用同名文件选择覆盖 | 是否保留文件 ID、版本号和原文件创建时间 |
| D-01 | 下载该文件 | 元数据请求、下载 URL、跳转、Range/Content-Length 和 Content-Disposition |
| R-01 | 重命名文件 | 目标 ID、名称字段和响应是否返回完整对象 |
| M-01 | 移动到测试子目录 | 源父目录、目标父目录和批量/单项语义 |
| X-01 | 删除测试文件或目录 | 是否软删除、是否需要回收站请求、错误码 |

`L-01`、`U-01`、`D-01`、`F-01`、`X-01`、`R-01` 和 `M-01` 已通过本人账号的专用测试目录完成初步观察；`U-02` 的浏览器分片流程也已观察，并已完成一次适配器真实回放。失败续传、取消/清理和分片覆盖仍待单独验证。删除实验仍应确认目标只在专用测试目录中。

## 浏览器操作细节

对每个实验：

1. 记录时间、当前目录 UI 名称、目标文件 UI 名称和大小。
2. 清空 Network 面板。
3. 执行一个动作，等待 UI 完成；上传或下载需要等待状态稳定。
4. 筛选 `fetch` / `xhr`，再按时间顺序查看请求。
5. 排除统计、埋点、头像、通知等与文件动作无关的请求。
6. 导出该轮 HAR 到本机的 `captures/` 目录。原始文件已被 `.gitignore` 忽略，仍需避免上传或粘贴。
7. 用 `tools/har_inspect.py` 做第一轮摘要和脱敏，再人工检查脱敏结果。

HAR 只用于本地分析。向外提供证据时，优先提供手工整理的请求记录；如果确实需要 HAR，应先删除登录流程、非 WPS 请求、响应文件内容，并确认所有认证值都已经替换。

## 重点观察项

### 列目录与目录模型

- method、完整路径和 query 参数名。
- 请求 body 中的父目录字段、分页游标、排序和过滤字段。
- 响应中区分文件/文件夹的字段，以及 `id`、`parent_id`、名称、大小、更新时间、哈希/ETag、回收站状态。
- 空目录、根目录、无权限目录和分页边界的行为。
- 是否需要先请求站点配置、租户信息或用户信息；这些只记录依赖关系，不扩大访问范围。

### 小文件上传

按时间顺序标记每个疑似请求：

- 初始化/预签名/上传会话请求。
- 实际内容请求的 host、method、Content-Type、Content-Length、Content-Range、Range、校验和和自定义头名称。
- 完成、确认或轮询请求，以及最终返回的文件对象。
- 失败、取消和重复文件名的行为。

如果出现对象存储域名或带签名的 URL，只记录域名、路径形状、参数名和有效期信息；签名值、Cookie 和 Token 必须脱敏。

### 下载与流式行为

- 是先取元数据再拿临时 URL，还是一个 API 直接返回内容。
- 是否发生 3xx 跳转，最终响应的 Content-Type、Content-Length、Content-Disposition 和 Accept-Ranges。
- 发送 `Range` 时是否得到 `206`、Content-Range，以及临时 URL 是否允许续传。
- 下载 URL 的有效期和是否只能使用一次；这些只通过本人账号的小文件实验观察。

### 鉴权与刷新

只记录认证机制的形状，不记录值：

- 认证信息出现在 Cookie、Authorization、请求 body 还是自定义 header。
- 是否有 CSRF 相关 header 或 cookie。
- 刷新请求的触发条件、字段名、状态码和返回的过期时间字段。
- 认证失败时的状态码和 UI 行为。

登录、SSO、验证码和风控流程不纳入适配器实现；适配器只处理在正常登录后已获得的会话续期能力，并遵守服务端限制。

## 最小证据记录

对每个候选请求至少记录：

```text
experiment: L-01
observed_at: 2026-09-01T00:00:00+08:00
action: open the test folder
method: GET
url: https://<redacted-host>/<redacted-path>?parent_id=<redacted-or-local-id>
request_headers: accept, content-type, <authentication-header-name-redacted>
request_body: none
status: 200
response_content_type: application/json
response_shape: { ... }
result_in_ui: three entries shown
evidence: observed
notes: pagination field still unknown
```

不要把这段示例中的占位符替换成真实 Token 后提交。真实发现写入 `docs/findings.md`，敏感原文留在本机。

## 停止条件

遇到以下情况暂停实验并先记录，不尝试绕过：出现权限错误、验证码/风控、请求被明确拒绝、需要他人共享数据，或无法判断某个操作是否仍属于本人账号范围。
